# Google Drive MCP

**Package:** `@piotr-agier/google-drive-mcp`
**Purpose:** Provides Claude with access to Google Drive files, folders, and documents

---

## ⚠️ CRITICAL: OAuth Authentication Required

**This MCP requires OAuth 2.0 authentication.** You MUST complete the OAuth flow before this MCP will work.

### Why OAuth?

Unlike Google Tasks MCP (which uses simple API credentials), Google Calendar and Drive MCPs use OAuth because they:
- Access user-specific data
- Require interactive user authorization
- Need refresh tokens for long-term access

---

## 🔐 Authentication Setup (Required)

### Step 1: Google Cloud Console Setup (One-time)

1. Go to https://console.cloud.google.com/apis/credentials
2. Create or select a project
3. Enable Google Drive API
4. Create OAuth 2.0 Client ID (Application type: Desktop app)
5. **Add these redirect URIs:**
   - `http://localhost:3000/oauth2callback`
   - `http://localhost:3000`
   - `http://localhost`
6. Download the credentials JSON file
7. Save to: `~/.claude/credentials/google-oauth.json`

**Expected file format:**
```json
{
  "installed": {
    "client_id": "YOUR_CLIENT_ID.apps.googleusercontent.com",
    "project_id": "your-project",
    "auth_uri": "https://accounts.google.com/o/oauth2/auth",
    "token_uri": "https://oauth2.googleapis.com/token",
    "auth_provider_x509_cert_url": "https://www.googleapis.com/oauth2/v1/certs",
    "client_secret": "YOUR_CLIENT_SECRET",
    "redirect_uris": [
      "http://localhost:3000/oauth2callback",
      "http://localhost:3000",
      "http://localhost"
    ]
  }
}
```

### Step 2: Complete OAuth Flow

**IMPORTANT:** Google Calendar and Drive share the same OAuth credentials and tokens. Complete this process ONCE to enable both MCPs.

#### Terminal 1 - Start OAuth Callback Server
```bash
cd ~/.claude/projects/code-execution-mcp
export PATH="$HOME/.bun/bin:$PATH"
bun run oauth-callback-server.ts
```

The callback server will:
- Listen on `http://localhost:3000`
- Catch the OAuth redirect from Google
- Exchange authorization code for tokens
- **Automatically save tokens to BOTH Calendar and Drive directories**

#### Terminal 2 - Trigger OAuth Flow
```bash
cd ~/.claude/projects/code-execution-mcp
export PATH="$HOME/.bun/bin:$PATH"
bun run manual-oauth-flow.ts
```

**Why `manual-oauth-flow.ts`?**
This script requests ALL required scopes (Calendar + Drive) in a single OAuth flow, ensuring one token works for both MCPs.

#### Browser - Authorize
1. Browser opens automatically to Google authorization page
2. Select your Google account
3. Review permissions:
   - Drive access (drive, files, spreadsheets, documents, presentations)
   - Calendar access (read, events, readonly)
4. Click "Allow"
5. Browser redirects to `http://localhost:3000/oauth2callback`
6. You'll see "✅ Authorization Successful!"

#### Verify
Terminal 1 should show:
```
✅ Received authorization code from Google
🔄 Exchanging authorization code for tokens...
✅ Successfully obtained tokens
💾 Saving tokens to both Calendar and Drive directories...
✅ Tokens saved to: ~/.config/google-calendar-mcp/tokens.json
✅ Tokens saved to: ~/.config/google-drive-mcp/tokens.json
🎉 OAuth flow completed successfully!
```

### Step 3: Test the MCP
```bash
export PATH="$HOME/.bun/bin:$PATH"
bun run test-google-drive.ts
```

Expected output:
```
✅ SUCCESS! Google Drive MCP is working.

📁 Root folder contents:
- Documents, spreadsheets, presentations
- Multiple files and folders listed
```

## 📁 File Locations

### Credentials
- **OAuth Client Config:** `~/.claude/credentials/google-oauth.json`

### Tokens (Auto-generated by OAuth flow)
- **Drive Tokens:** `~/.config/google-drive-mcp/tokens.json`
- **Calendar Tokens:** `~/.config/google-calendar-mcp/tokens.json`

**Note:** Both token files are identical and contain the same OAuth token with all scopes.

### OAuth Helper Scripts
Located in `~/.claude/projects/code-execution-mcp/`:
- `oauth-callback-server.ts` - Handles OAuth callback and saves tokens
- `manual-oauth-flow.ts` - Triggers OAuth flow with all scopes

---

## 🔧 How This MCP Loads Credentials

The MCP uses `load_credentials.ts` which:

1. Looks for OAuth credentials at: `~/.claude/credentials/google-oauth.json`
2. Looks for tokens at: `~/.config/google-drive-mcp/tokens.json`
3. Creates OAuth2 client with credentials
4. Uses tokens for authentication
5. Automatically refreshes access tokens when expired

**Important:** The MCP will NOT work without both files present.

## 🚨 Common Issues & Solutions

### Issue 1: "Not Found" when redirected to localhost
**Cause:** OAuth callback server not running
**Fix:** Start `oauth-callback-server.ts` in Terminal 1 BEFORE triggering OAuth flow

### Issue 2: "redirect_uri_mismatch" error
**Cause:** Google Cloud Console missing required redirect URIs
**Fix:** Add `http://localhost:3000/oauth2callback` to your OAuth client's redirect URIs in Google Cloud Console

### Issue 3: "Insufficient authentication scopes"
**Cause:** OAuth token missing required scopes
**Fix:** Delete tokens and re-run OAuth flow using `manual-oauth-flow.ts`:
```bash
rm ~/.config/google-calendar-mcp/tokens.json
rm ~/.config/google-drive-mcp/tokens.json
# Then follow OAuth flow steps above
```

### Issue 4: MCP can't find credentials
**Cause:** Credentials file in wrong location or wrong format
**Fix:** Verify `~/.claude/credentials/google-oauth.json` exists and matches the format shown above

### Issue 5: Drive works but Calendar doesn't (or vice versa)
**Cause:** Tokens only in one directory
**Fix:** The updated `oauth-callback-server.ts` saves to both directories automatically. If using an old version, manually copy:
```bash
cp ~/.config/google-drive-mcp/tokens.json ~/.config/google-calendar-mcp/tokens.json
```

## 🔑 OAuth Scopes Used

This MCP requires the following Google Drive scopes:
- `https://www.googleapis.com/auth/drive`
- `https://www.googleapis.com/auth/drive.readonly`
- `https://www.googleapis.com/auth/drive.file`
- `https://www.googleapis.com/auth/spreadsheets`
- `https://www.googleapis.com/auth/documents`
- `https://www.googleapis.com/auth/presentations`

**Note:** The OAuth flow also requests Calendar scopes so one token works for both MCPs.

---

## 🔄 Token Refresh

OAuth access tokens expire after ~1 hour. The MCP automatically uses the refresh token to obtain new access tokens when needed. You don't need to re-authorize unless you revoke access or delete the tokens.
